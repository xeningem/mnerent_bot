# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Назначение

Открытый Telegram-бот для поиска долгосрочной аренды в Черногории с личными фильтрами, которые настраиваются кнопками. По умолчанию: любой город, до 800 €/месяц, от двух спален, аренда на весь год. Подробности запуска и ограничения первой версии — в `README.md`.

## Команды

Запускать из корня репозитория: путь к сессии `data/reader` относительный. Требуется Python 3.11+, образ Docker использует 3.12. Линтер и сборка не настроены.

```bash
python -m unittest discover -s tests -v                        # все тесты
python -m unittest tests.test_core.ParserTests.test_serbian    # один тест

python app.py login    # интерактивный вход в Telegram, показывает OWNER_ID
python app.py scan     # однократный сбор без бота
python app.py export   # кандидаты владельца в JSON (stdout), с его фильтрами; --all добавляет отклонённые
python app.py reparse  # пересчитать parse() для уже собранных записей
scripts/backup.sh      # копия базы, сессии и .env в ~/Backups/mnerent_bot (KEEP=14 последних)
python app.py run      # сбор и бот; параметры: --days 14 --interval 600 --rescan-days 3 --deep-hours 6
```

В Docker те же команды выполняются через `docker compose run --rm bot python app.py <команда>`, сервис запускается через `docker compose up -d`.

## Архитектура

- `core.py` использует только стандартную библиотеку: `parse()`, `Store` (SQLite), `card()`, список `SOURCES`. Тесты импортируют только его, поэтому работают без установки зависимостей.
- `app.py` содержит сбор и бота. `telethon`, `aiohttp` и `dotenv` импортируются внутри функций.
- В Telegram два независимых подключения. Сообщения читает пользовательская сессия Telethon (`data/reader.session`), а бот работает с Bot API напрямую через `aiohttp` и `getUpdates`. Пользовательский аккаунт ничего не отправляет.
- `run` выполняет `scanner()` и `bot_loop()` в одном цикле asyncio с общим соединением SQLite. Две копии сборщика с одной сессией запускать нельзя.
- Источники — публичные группы, а не каналы: в них есть обычная переписка, а веб-превью `t.me/s/<имя>` недоступно.

## Неочевидные правила

- **Результат `parse()` хранится в `posts.parsed`.** `Store.put` пересчитывает его только при изменении текста поста, поэтому после правок парсера нужен `python app.py reparse`.
- **`parse()` не знает о пользователях.** Он отклоняет только то, что не подходит никому (не аренда, продажа, посуточная аренда, нежильё). Город, цену, спальни, район, срок и слова проверяет `filter_reasons()` при выдаче, поэтому смена фильтра не требует `reparse`.
- **Новые поля в `parse()`:** подними `PARSE_VERSION`, и `Store` сам пересчитает записи при старте.
- **Город — исключение из правила про явные признаки:** при выбранном городе пост без города скрывается, потому что большинство источников охватывают всю страну. Цена, спальни и район без значения пост не скрывают, если пользователь не включил скрытие неполных объявлений.
- **Районы (`DISTRICTS`):** конкретное название определяет и город, а другие города, упомянутые только по названию («15 мин до Бара», `#Бар`), в этом случае отбрасываются (`located` в `parse()`). Район показывается по месту, даже если это другая община: «Круче» записан под Ульцинем, поэтому поиск по Бару такие дома не показывает. `GENERIC_DISTRICTS` (центр, старый город) есть во многих городах и относятся только к городам, названным в посте. Выбор района сужает только свой город.
- **Меню фильтров:** экраны и обработка кнопок — чистые функции `menu()`, `apply_choice()`, `apply_text()` в `core.py`. `callback_data` ограничен 64 байтами, поэтому города и районы передаются индексами: новые значения добавляй в конец списков, иначе старые кнопки сработают неверно.
- **`started` означает завершённую настройку.** Пока он равен 0, меню работает как три шага и уведомления не отправляются. `awaiting` хранит, какое значение пользователь вводит текстом.
- **Статусы только `reject` и `review`.** Непустой `reasons` даёт `reject`, а `unknown` только добавляет пометки в карточку. Отклонять можно только по явному признаку: ложный `reject` теряет квартиру без следа, а лишний `review` стоит одного просмотра. Автоматического статуса «подходит» намеренно нет: условия подтверждаются вручную у автора.
- **Уведомления зависят от `posts.changed`, `user_posts.notified` и `notify_after`.** `changed` меняется только при появлении поста или правке текста, а `seen` обновляет каждое чтение, поэтому границу сравнивают с `changed`. Граница — большее из глобального `meta.notify_after` (ставится после первого сбора) и `users.notify_after` (ставится при `/allow` и смене фильтра), поэтому массовой рассылки нет. При изменении текста `Store.put` сбрасывает `notified` у всех пользователей, поэтому пост приходит снова.
- **Полная история читается один раз.** Обычный проход читает только сообщения новее `Store.last_id()`. Раз в `--deep-hours` часов (`scan_due()`) перечитывается окно, чтобы заметить правки. Метка `scanned:<source>` в `meta` двигается только после успешного чтения окна, а `scan_days()` выбирает окно с учётом простоя, чтобы лишний раз не нагружать личный аккаунт.
- **Бот стартует до первого сбора.** `scanner()` сначала собирает, затем ставит `notify_after`; пока метки нет, бот ничего не рассылает, поэтому первая загрузка проходит без уведомлений.
- **Цены разбираются до `norm()`:** перевод строки разделяет несвязанные числа, а `norm()` его схлопывает. Число без валюты считается ценой только рядом со словами «цена», «стоимость», 💶, 💰 или с периодом «/мес», «в месяц». Лишние суммы (депозит) могут снизить `min_price`, но это безопасно: цена отсеивает пост, только если даже меньшая сумма выше предела.
- **Спальни без числа:** единственное упоминание «спальня» рядом с «гостиная» считается одной спальней, если нет признаков другой комнаты для сна (детская, кабинет, «3-комнатная»).
- **`unknown` в карточке — только то, чего нет в этом посте и не видно в заголовке.** Общие оговорки сюда не добавляй: они есть в `/help` и в шапке HTML-файла, а карточка остаётся компактной (одна строка «дата, автор» без подписей).
- **`BAR_SOURCES`:** в этих группах Бар подразумевается и может не упоминаться в тексте.
- **Дедупликация:** точная по хешу нормализованного текста и узкая по `same_listing()` (тот же автор, все числа в тексте совпадают, кроме полных дат вида 1.06.2026, которые правят при репосте, сходство ≥ 0,95). Выполняется в `Store.candidates`, а для уведомлений в `Store.duplicate_notified`. Один шаблон с другой ценой остаётся отдельным постом. Скрытие действует на одну запись и одного пользователя, поэтому её копия из другого источника остаётся в выдаче; `StorageTests` это закрепляет.
- **Схожесть текстов считается по `plain()`, а не по `norm()`:** `plain` дополнительно заменяет эмодзи пробелами, чтобы смена смайлика не была правкой. `norm()` и `digest` менять нельзя: хеш изменится у всех постов, бот сочтёт их отредактированными и разошлёт заново.
- **Повторы и «Похожее»:** `Store.annotate(rows, pool)` добавляет к строкам `copies`/`first` (сколько раз и с какой даты автор публиковал этот текст, включая схлопнутые ближние копии из `absorbed`) и `related` (посты того же автора со сходством ≥ 0,95, но с другими числами: другая квартира шаблона или переоценка). `card()` выводит это блоком под текстом и ссылками, перед ссылкой на пост (шапка остаётся компактной, пометки ↓ в ней нет); `export_html()` показывает «повторов: N, впервые …» и «Похожее #id (дата): было € → стало € (±Δ)». `price_drop` — наибольшее снижение цены относительно более старого похожего поста (0, если нет); `/find` и `export_rows` ставят такие посты первыми (сортировка устойчивая, остальные по дате), в HTML это сортировка по умолчанию. `related` ищется только среди `pool` (обычно кандидаты пользователя) и ничего не скрывает; снижение цены — подсказка, а не вывод: так же выглядят соседние квартиры одного шаблона.

- **В логах и `health` только имя класса исключения**, чтобы текст ошибки не раскрыл токен или данные сессии.
- **`Dockerfile` копирует только `core.py` и `app.py`.** Новый модуль нужно добавить туда же.
- **`page_size` (по умолчанию 5, максимум `MAX_PAGE_SIZE` = 50)** лежит в фильтрах, но ничего не отбирает: смена только его не двигает `users.notify_after` (см. `Store.set_filters`).
- **`/file`:** `export_html()` в `core.py` — чистая функция, собирает один самодостаточный HTML из `Store.export_rows` (кандидаты `/find` плюс избранное пользователя, даже скрытое, старое или не прошедшее фильтры); бот отправляет его через `sendDocument`. Сортировка, поиск и фильтры в файле — встроенный `EXPORT_JS` по `data-*` атрибутам карточек; без JavaScript остаётся статичный список. Весь пользовательский текст проходит через `html.escape`. Не используй вложенные f-строки с одинаковыми кавычками: нужен Python 3.11.
- **Избранное:** `user_posts.favorite`, личное, как `hidden`, но независимо от него и от фильтров. Кнопка на карточке (`fav:`/`unfav:`), `/favorites`, ★ в `card()` и в экспорте.
- **Проверка парсера:** отметка ставится только ответом владельца (reply) на карточку; кнопки на карточке для этого нет. Отметки лежат в `parser_reports` (с результатом `parse()` на момент отметки), список — `/reports` или `python app.py export --reports`. Отметка не влияет на выдачу и не зависит от «Скрыть».
- **Состояние бота:** в `meta` лежат `offset`, `notify_after`, `scanned:<source>`; в `users` — фильтры, `page`, `started`, `paused`, `notify_after`; в `user_posts` — `hidden`, `favorite`, `notified`.
- **Доступ открыт всем.** Первое личное сообщение создаёт строку в `users`. Владелец (`OWNER_ID`) видит `/users`, а `/deny` и `/allow` меняют `users.blocked`.
- **Доставка порциями:** за один проход пользователь получает не больше `DELIVERY_BATCH` постов, чтобы чужая очередь не задерживала ответы остальным.
- **Миграция однопользовательской базы** в два шага: `Store.upgrade_posts()` добавляет колонки, сбрасывает `scanned:*` (следующий проход заполнит автора и ссылки) и делает `reparse`; `Store.adopt_owner()` передаёт старое состояние владельцу и удаляет старые колонки.
- **Кнопки со ссылками:** в текущем Telethon адрес лежит в `button.type.url`, а не в `button.url`; `message_links()` проверяет оба варианта.
